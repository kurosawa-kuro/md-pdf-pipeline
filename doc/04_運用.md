# 運用ガイド

> **環境構築（STEP 1〜）** + 定常運用 + インシデント対応 + ロールバック。
> 手順・閾値・アラート変更時に更新する。STEP は上から順に叩いて完走することが品質基準。

## 1. 環境構築（上から順に実行）

### STEP 1: 前提ツールをインストール
```bash
sudo apt update
sudo apt install -y python3 python3-pip fontconfig fonts-noto-cjk
```

### STEP 2: ツール到達確認
```bash
python3 --version
python3 -m pip --version
fc-match "Noto Sans CJK JP"
```

### STEP 3: 依存を入れる
```bash
make setup
```

### STEP 4: 静的検証 + テスト
```bash
make lint && make test
```

### STEP 5: ローカル起動
```bash
make run
```

## 2. 定常運用

### 2.1 定常サイクル
- Markdown を原本として更新する
- `make test` で変換と静的検証を確認する
- 生成された PDF を `out/` 配下で確認する

### 2.2 日次チェック
- 日本語フォントが利用可能か
- `requirements.txt` と実行環境が乖離していないか
- `out/` 配下の生成物が意図どおり出ているか

### 2.3 手動操作
- 単一 Markdown を PDF に変換

```bash
python3 src/cli.py path/to/input.md
```

- 出力先を指定して変換

```bash
python3 src/cli.py path/to/input.md -o out/custom.pdf
```

- フォント厳格チェックを外して変換

```bash
python3 src/cli.py path/to/input.md --allow-missing-font
```

### 2.4 変更運用（コード / 設定変更時）
- 仕様変更時は `doc/01` と `doc/02` を先に合わせる
- 実装ファイル追加や構成変更時は `doc/03_実装カタログ.md` を更新する
- コマンドや手順変更時は `Makefile` と本書を同時更新する

### 2.5 シークレットローテーション
- 現時点では秘密情報を利用しないため対象外
- 将来追加時は `env/secret.yaml` または Doppler の採否を仕様書に反映してから運用へ組み込む

## 3. インシデント対応

### 3.1 日本語が文字化けする
- 症状: PDF は生成されるが、日本語が豆腐化または別フォント崩れする
- 一次対応:
  - `fc-match "Noto Sans CJK JP"` でフォント存在を確認する
  - `fonts-noto-cjk` が未導入なら導入する
- 恒久対応:
  - 環境構築手順にフォント確認を残す
  - CSS のフォント指定を勝手に変更しない

### 3.2 `weasyprint` が見つからない
- 症状: CLI 実行時に `weasyprint is not installed` エラーになる
- 一次対応:
  - `make setup` を再実行する
  - `python3 -m pip show weasyprint` で導入状態を確認する
- 恒久対応:
  - `requirements.txt` を正として依存を管理する

### 3.3 入力ファイル不正
- 症状: 入力ファイル未存在、非 UTF-8、`.md` 以外で失敗する
- 一次対応:
  - 入力パスを確認する
  - UTF-8 で保存し直す
- 恒久対応:
  - 原本は `.md` かつ UTF-8 に統一する

## 4. ロールバック早見表

| 事象 | ロールバック手順 |
|---|---|
| 変換ロジック変更で PDF が壊れた | `src/` の変更を戻し、`make test` が通る直前状態へ戻す |
| CSS 変更でレイアウトが崩れた | `src/styles/print.css` を直前安定版へ戻し、`make run` で再確認する |
